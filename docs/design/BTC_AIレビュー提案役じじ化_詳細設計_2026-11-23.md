# BTC AIレビュー 提案役のじじ化 詳細設計（2026-11-23）

## 背景
- 夜間AIレビュー（ai-review.timer、毎日03:30）は2026-11-12以降、提案役 Groq（openai/gpt-oss-120b）の TPM 上限エラー（413、limit 8,000 に対し requested 8,309→8,663 と増大）で毎晩失敗し、設定は 2026-11-11 版で凍結されている。
- 本人決定（2026-11-23）：議論のAIを単一にしないため、懐疑役＋最終決定役の Gemini は現行のまま残し、提案役（Proposer）の席をじじ（Muse）が担う。「じじがシステムの一部として動く」進め方。

## 役割分担（変更後）
- VPS側（機械処理）：build_change_outcomes.py → build_ai_review_summary.py → build_proposer_prompt.py（提案役プロンプトのファイル化）までを従来どおり03:30に実行する。
- じじ側（定時ジョブ 03:40）：プロンプトファイルを読み、提案役プロンプトの system 指示に厳密に従って提案文を作成し、提案ファイルとしてVPSへ戻す。続けて review_pipeline.py を --proposer-file 付きで起動し、結果（decision JSON）を確認する。
- Gemini側：懐疑役・最終決定役・バリデーション・config適用・Telegram結果通知はすべて現行コードのまま不変。

## 変更内容
1. `ai_review/review_pipeline.py`
   - `--proposer-file <path>` 引数を追加。live モードで指定された場合、Groq を呼ばずファイル内容を提案役出力として使う。
   - ファイルが存在しない／空の場合は例外とし、既存の failed_before_moderator 経路（decision JSON への記録、日次レポートへの集約）に乗せる。Groq への暗黙フォールバックはしない。空文字列が渡された場合も「未指定」とは扱わずエラーにする。
   - 対象日との結び付け：ファイル名が `ai_review_proposer_output_<target_date>.txt` と一致しない場合はエラーにし、別日の提案で設定が変わることを防ぐ。
   - サイズ上限 32,768 バイト（Groq 経路の max_tokens=2000 の提案文を十分に上回る範囲）。超過はエラー。
   - 読み取りは utf-8-sig（BOM が付いていても提案文へ混入しない）。
   - decision JSON に `proposer_source`（"stub" / "file" / "groq"）を記録し、ファイル経路では `proposer_file`（パス）と `proposer_file_sha256` も記録して監査可能にする。
   - test_mode のスタブ動作は従来どおり最優先（ファイルより先にスタブを返す）。
2. `ai_review/build_proposer_prompt.py`（新規）
   - 対象日（省略時は前日）のサマリー JSON を読み、prompts.build_proposer_prompt で生成した system / prompt を `log/ai_review_proposer_prompt_<date>.json`（{target_date, generated_at, system, prompt}）へ書く。
   - Groq に渡していたのと同一のプロンプトをファイル化するため、入力の同一性が保たれる。
   - サマリーが無い場合は exit 1。
3. `ai_review/run_nightly_review.sh`
   - 環境変数 `AI_REVIEW_PROPOSER_MODE`（既定 "groq"＝現行動作）を追加。"jiji" のときはサマリー成功後に review_pipeline.py の代わりに build_proposer_prompt.py を実行して終了する。
   - モードの実設定は VPS の ai_review/.env（compose の env_file）で行う。コードの既定は groq のため、未設定環境では従来動作のまま。
   - 未知のモード値は黙って groq 経路へ倒さず、開始直後にエラー終了する（タイポ等の誤設定を loud に検出するため）。
   - ロックファイルの置き場所をスクリプト同階層から log ディレクトリ（bind mount でコンテナをまたいで共有）へ移す。ai_review は使い捨てコンテナ実行のため、従来位置では実行をまたいだ直列化になっていなかった。
4. `ai_review/run_pipeline_locked.sh`（新規）
   - じじ側ジョブが review_pipeline.py を起動するためのラッパー。夜間スクリプトと同じロック（log ディレクトリ、新鮮なロックがある場合は exit 1）を取得してから実行し、config を書く工程が直列化されるようにする。
- なお `ai_review/run_nightly_review.ps1`（Windows 用の開発バリアント）は本番では使われていない（本番は systemd → docker → .sh）ため、本変更の対象外とする。

## ファイル契約
- プロンプト：`log/ai_review_proposer_prompt_<target_date>.json`
- 提案：`log/ai_review_proposer_output_<target_date>.txt`（UTF-8テキスト）
- 対象日は両者とも「前日」で一致させる。じじ側ジョブは対象日を明示してパイプラインを起動する。

## フェイルセーフ
- じじ側ジョブが回らない／提案ファイルが無い夜は、パイプライン自体が起動されず、その夜は設定変更なし（安全側）。
- 提案ファイルが空・欠落のままパイプラインが起動された場合は failed_before_moderator で記録され、config は変更されない。
- ロールバック：ai_review/.env の AI_REVIEW_PROPOSER_MODE を外す（または groq に戻す）と、翌晩から従来の全自動フローに戻る。

## テスト
- tests/test_proposer_file_mode.py を追加：ファイル経路の返却、Groq未呼び出し、欠落／空ファイルの例外、スタブ優先、Groq経路の不変、プロンプトファイル書き出し関数の検証。
- 全体テストでベースライン（411 passed / 10 failed、失敗は既存の ffmpeg・public report 関連）と比較し、失敗集合が同一であることを確認する。

## デプロイ
- GitHub へ PR → マージ後、VPS で git pull + docker compose build（ai_review はオンデマンド実行のため新イメージは翌回の compose run から有効。稼働中エンジンには触れない）。
- VPS の ai_review/.env に AI_REVIEW_PROPOSER_MODE=jiji を追記する。
- じじ側の定時ジョブ（毎日03:40、goal: btc-automated-trading-system-handover 配下）を新設する。
