## (a) 既存認識と一致した要点

- 対象は GMOコイン BTC/JPY、リポジトリは `gmo-btc-ws`（GitHub: festallypicco/gmo-btc-ws、Private）。VPS 本番・実資金で稼働（詳細は (c) の開始日参照）
- 毎晩の AI 設定レビュー：Groq が Proposer、Gemini が Skeptic/Moderator を担い、外れ値検知＋段階適用（カナリア）で config を見直す（§5）
- カナリアは 3 段階（[30%, 60%, 100%]）で、外れ値と判定された変更のみに適用される（§5.4.2）
- 日次成績を X・Instagram Reels・Threads へ自動投稿する（§4.6・§4.7。ただし投稿方式は (b) 参照）
- VPS は ConoHa Ubuntu 24.04、Docker＋systemd タイマーで稼働。SSH ポート 2222、ダッシュボードは SSH トンネル経由（外部公開しない方針）
- 監視に Telegram を使用（用途・システムごとに Bot を分離。内部管理用と SNS 投稿用の 2 系統）
- ログに絵文字・特殊 Unicode を使わない運用ルールが §9 の Cursor 向け定型文にも明記されている

## (c) 新しく分かった重要点

1. **実資金本番の開始日は 2026-08-01**。ConoHa VPS 実機構築と `trading_mode=real` への本番切替が同日。それ以前は Windows ネイティブでの仮想資金運用＋ `docker-compose.real-test.yml` による実資金隔離テスト（フェーズ2）の段階だった。既存認識には開始日の情報がなかった
2. **AI の具体的なモデル名**（既存認識はプロバイダ名のみだった）
- Proposer: Groq `openai/gpt-oss-120b`
- Skeptic / Moderator: Gemini `gemini-3.5-flash`（いずれもフル版入力、Moderator は JSON のみ出力）
- 集計ウィンドウは 前日（異常検知）／14日（メイン判断）／30日（安定性）／90日（レジーム参照）。設定変更の事後評価（build_change_outcomes）もプロンプトに含まれ、過去の変更の成否を次回提案に活かす設計
3. **AI レビューの実行時刻は 03:30**（当初 00:30 だったが Gemini 503 多発を受け変更）。反映は 06:00 のエンジン再起動。人間の事前承認は挟まず、Telegram は事後報告のみ（§9 に検討経緯あり）
4. **ガードレールは既存認識より多段**。カナリア以外に次がある：
- 変更幅の相対上限 ±15%／回、絶対範囲チェック（PARAMETER_ABSOLUTE_BOUNDS）
- プロファイル名セットが一致しない提案は自動適用せず保留（held）
- **バックテスト検証ゲート**（2026-07-17 実装、§5.4.3）：主要3パラメータの変更を過去30日の板スナップショットで簡易シミュレーションし、悪化判定なら適用しない。既存認識には無かった
- カナリアの段階は暦日ではなくレビュー実行回数で進むため、日中の手動再実行は段階を意図せず進めうる（§9 の運用上の注意）
5. **監視群の厚み**：孤児注文監視（5分間隔、GMO の有効注文と内部状態の突き合わせ。自動キャンセルはしない）、取引異常検知（1時間毎）、CSV/DB 整合性チェック、クラッシュループ検知、監視スクリプト自体の死活監視（ハートビート）など複数層。サーキットブレーカーは発注レート超過＋日次損失（開始時残高比 10%）の2系統
6. **SL に関する v90 時点の仕組み**：起動時の突き合わせ（`reconcile_real_state_on_startup()`）で、保有中ポジションの TP/SL の欠落を判定し、欠落側のみ再発注する。同一建玉で2回連続して解消しない場合は再発注せず安全停止に切り替える（§9・3.4系）。これは「起動時」限定の仕組み
7. **直近インシデント 7.27（2026-08-19〜21、v90 の主題）**：order_rate_limit 頻発（8/20 の相場急変で取引回数が平常の約10倍）→ サーキットブレーカーで manual_stop → 06:00 再起動が SKIP され約15時間停止し、`trading_day_date` が固着して daily_history.jsonl に重複行が発生。対応3点（重複追記ガード／実時刻ベースのロールオーバー追加／再エントリークールダウン 5秒→10秒）は実施・VPS 反映済み。ただし **PAUSED 状態が長引くこと自体を検知する監視は未実装**で §9 の残課題
